Security & trust

Protection should feel quiet.

The interface makes protected actions visible without turning the experience into a wall of warnings.

✓
JWT-authenticated APIs

Protected backend routes require the existing authentication token.

⌁
Password hashing

The backend uses bcryptjs for password hashing and verification.

◈
Demo safeguards

Balance visibility and money movement include the existing four-digit demo passcode.

Important distinction

Built for demonstration, not production banking.

Ledger intentionally keeps simulated capabilities labelled as simulations. It should not be connected to real financial infrastructure without a proper security and compliance review.

!
Local database

SQLite is used for the project backend.

!
Demo OTP flow

Registration/reset OTP behavior is for local demonstration.

!
Simulated services

External payment networks are not connected.
